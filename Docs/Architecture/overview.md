# Общая архитектура

## Принципы (из GDD, раздел 2)

1. **Все игровые системы реализуются отдельно друг от друга.**
2. **Одна базовая сцена** (`scenes/main/Main.tscn`) — всё остальное загружается внутрь неё.
3. **Активное наследование**: если сущность похожа на существующую — наследуемся, а не копируем.
4. **Ноль хардкода**: все числовые значения — в конфигах `.tres` (см. [config-system.md](config-system.md)).

## Слои

```
Автолоады (Game, Events, Trust, Configs)   <- состояние и данные, без визуала
        │
Main.tscn (единственная базовая сцена)     <- контейнер, переключает состояния
        │
Сцены состояний (меню, интро, версии)      <- появятся на этапе прототипа
        │
Компоненты (мини-игры, UI, эффекты)        <- наследники базовых классов
```

## Потоки данных

- Состояние игры хранится **только** в автолоаде `Game`. Сцены не решают, «что дальше».
- Системы сообщают о событиях через сигналы `Events` (шина). Прямые вызовы между сценами запрещены.
- Числа баланса читаются через `Configs` (например, `Configs.balance.trust_max`).

### Пример потока

1. Мини-игра «Сбор слов» собрала 3 слова → вызывает `succeed()` (метод `BaseMinigame`).
2. `Events.minigame_succeeded` ловит контроллер версии 0.1.
3. Контроллер просит `Game.change_state(Game.State.VERSION_2)`.
4. `Events.game_state_changed` ловит `Main` и подменяет содержимое сцены.
