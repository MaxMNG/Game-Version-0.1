# План реализации прототипа Version 0.1

> Источник ТЗ: `References/GDD/Прототип/Прототип - Version 0.1.md`.
> Этот план — рабочий чеклист. Выполняем строго по шагам, каждый шаг завершаем
> проверкой по критериям приёмки. Статусы: ⬜ не начат / 🔄 в работе / ✅ готов.

**Общие правила для всех шагов:** ноль хардкода (все числа — в конфиги `.tres`),
наследование от `BaseMinigame` для мини-игр, общение через `Events`,
после каждого шага — импорт + дымовой тест (команды в `AGENTS.md`).

---

## Шаг 0. Контент-инфраструктура ⬜

**Цель:** таблицы слов/предложений можно редактировать в CSV и конвертировать в игру.

**Создаём:**
- `Content/words_v01.csv` — 10 слов (спецификация: [content-words-v01.md](content-words-v01.md))
- `Content/sentences_v02.csv` — наборы слов + предложения (спецификация: [content-sentences-v02.md](content-sentences-v02.md))
- `Game/scripts/resources/word_entry.gd` — `class_name WordEntry` (word, type, trust_effect, speaker, reaction_text)
- `Game/scripts/resources/sentence_entry.gd` — `class_name SentenceEntry` (+ `set_id`, words)
- `Game/scripts/resources/content_table.gd` — обёртки-ресурсы с массивами записей
- `Tools/convert_content.py` — конвертер CSV → `Game/resources/content/*.tres`
- Загрузка контент-таблиц в автолоад `Configs`

**Наполнение таблиц:** делаю я (черновик) → ты правишь в Excel. 10 слов: ≥1 хорошее, ≥1 плохое,
остальные нейтральные. Наборы v0.2: 3–4 штуки, в каждом 2–5 предложений (мин. 1 плохое + 1 хорошее).

**Критерий приёмки:** конвертер собирает `.tres` без ошибок; `Configs` отдаёт таблицы;
в игре доступны все 10 слов и наборы.

## Шаг 1. Небула-фон ⬜

**Цель:** живой фон всей игры — «цветовое нечто» как на референсе
(`References/Images/Pasted image 20261017160244.png`): тёмный фон, фиолетово-пурпурные
и зелёные чернильные облака; реагирует на курсор и затухает обратно.

**Создаём:**
- `Game/assets/shaders/nebula_background.gdshader` — fbm-шум, анимация по времени,
  `uniform` позиции/силы курсора (возмущение с экспоненциальным затуханием), приглушённая палитра
- `Game/scenes/effects/nebula_background.tscn` + `scripts/effects/nebula_background.gd` —
  полноэкранный `ColorRect` с `ShaderMaterial`, передаёт позицию мыши в шейдер
- `Game/scripts/resources/nebula_config.gd` + `resources/configs/nebula.tres` —
  цвета, скорость, сила/радиус влияния курсора, яркость

**Критерий приёмки:** фон красивый, но не отвлекает (это фон всей игры);
возмущение от курсора плавно затухает; 60 FPS на Compatibility.

## Шаг 2. Главное меню ⬜

**Цель:** состояние `Game.State.MENU` по ТЗ.

**Создаём:**
- `Game/scenes/ui/main_menu.tscn` + `scripts/ui/main_menu.gd`:
  - чёрный экран + небула-фон (приглушённый вариант) или тонкий «хай-тек» эффект
  - логотип **VERSION 0.1**: появляется через 1 с после запуска, «печатается» с мигающей кареткой
  - кнопка **НАЧАТЬ ИГРУ**: появляется через 1 с после логотипа → `Game.change_state(INTRO)`
  - незаметная подпись «alpha» внизу экрана
- `Game/scripts/resources/menu_config.gd` + `resources/configs/menu.tres` —
  задержки, скорость печати, тексты
- Подключение сцены состояния в `main.gd` (реестр состояний → сцены)

**Критерий приёмки:** игра запускается в меню; тайминги появления соответствуют ТЗ;
клик по кнопке переводит в INTRO.

## Шаг 3. Диалоговая система ⬜

**Цель:** баблы с «печатающимся» текстом и очередью реплик (нужны для интро, реакций, кат-сцен).

**Создаём:**
- `Game/scenes/ui/dialogue_bubble.tscn` + `scripts/ui/dialogue_bubble.gd` —
  панель + текст с typewriter-эффектом, автоскрытие/смена
- `Game/scripts/ui/dialogue_player.gd` — компонент очереди: массив реплик
  (спикер, текст, пауза), проигрывание по порядку, сигнал о завершении очереди
- `Game/scripts/resources/dialogue_line.gd` — ресурс реплики (speaker_id, text, pause_after)
- Подключение к `Events.dialogue_line_requested`

**Критерий приёмки:** очередь из 3+ реплик проигрывается корректно
(спикер виден, текст печатается, паузы работают); очередь сигналит о завершении.

## Шаг 4. Интро «Рождение ИИ» ⬜

**Цель:** состояние `Game.State.INTRO` по ТЗ — «волшебный» момент рождения.

**Создаём:**
- `Game/scenes/effects/flash_overlay.tscn` — полноэкранная вспышка (белая, быстрая)
- `Game/scenes/intro/intro.tscn` + `scripts/intro/intro.gd`:
  1. Чёрный экран → вспышка → появляется небула-фон
  2. 3 секунды свободной игры с фоном (курсор размазывает «краску»)
  3. Диалог (dialogue_player): mom «Запустила!» → dad «Да, кажется работает» →
     mom «Попробуем настроить его?» → dad «Загружаю веса» (тексты — EN, в конфиге)
  4. `Game.change_state(VERSION_1)`
- `Game/scripts/resources/intro_config.gd` + `resources/configs/intro.tres` —
  длительность свободной игры, реплики, тайминги

**Критерий приёмки:** интро проигрывается от вспышки до перехода без кликов;
тайминги и порядок реплик по ТЗ; переход в VERSION_1.

## Шаг 5. Версия 0.1 — сбор слов ⬜

**Цель:** мини-игра по ТЗ и [../Mechanics/word-assembly.md](../Mechanics/word-assembly.md).

**Создаём:**
- `Game/scenes/minigames/word_assembly.tscn` + `scripts/minigames/word_assembly.gd`
  (наследник `BaseMinigame`):
  - спавн облака: буквы текущего слова из `WordsTable` + 7–12 «мусорных» глифов;
    медленное плавание (синусоидальный дрейф), облако-сетка в центре
  - клик по символу — выделение зелёным свечением; повторный клик снимает;
    при 3 выбранных — проверка
  - проверка: буквы == слову из таблицы → успех (реплика `speaker` + `Trust.change(trust_effect)`);
    иначе — красное мигание + реплика `dad` + новый набор (без наказания)
  - 3 успеха → `succeed()` → запрос апгрейда
- `Game/scenes/ui/floaty_symbol.tscn` + `scripts/ui/floaty_symbol.gd` — кликабельный символ
- `Game/scenes/ui/trust_indicator.tscn` + `scripts/ui/trust_indicator.gd` —
  смайлик + стрелка ↑/↓, слушает `Events.trust_changed` (точных чисел не показывает)
- `Game/scripts/resources/version1_config.gd` + `resources/configs/version1.tres` —
  кол-во мусора, скорость плавания, слов для победы (3), реплика на «нет слова»

**Открытый вопрос (решу по умолчанию «да», поправь если не так):** порядок букв при выборе
не важен — засчитываем любую перестановку букв слова.

**Критерий приёмки:** 3 слова → апгрейд; «плохое» слово → −1 доверие и стрелка ↓;
«чушь» → красное мигание и повторный набор; проиграть невозможно.

## Шаг 6. Кат-сцена апгрейда ⬜

**Цель:** переход версия 0.1 → 0.2 по ТЗ.

**Создаём:**
- `Game/scenes/effects/upgrade_cutscene.tscn` + `scripts/effects/upgrade_cutscene.gd`:
  1. Диалог: mom «Молодец!» → dad «Неплохо... Можем пойти дальше» →
     mom «Дадим ему больше переменных?» → dad «Да, посмотрим как он справится»
  2. Экран сжимается в точку (tween масштаба) → вспышка
  3. `Game.change_state(VERSION_2)`

**Критерий приёмки:** кат-сцена не пропускает игрока вперёд кликами до конца диалога;
переход в VERSION_2 после вспышки.

## Шаг 7. Версия 0.2 — сбор предложений ⬜

**Цель:** мини-игра по ТЗ и [../Mechanics/sentence-assembly.md](../Mechanics/sentence-assembly.md).

**Создаём:**
- `Game/scenes/minigames/sentence_assembly.tscn` + `scripts/minigames/sentence_assembly.gd`
  (наследник `BaseMinigame`):
  - старт: баннер «Вы были улучшены до версии 0.2»; фон + еле заметная сетка
  - слова набора вылетают из центра (чипы) + неразборчивый мусор
  - игрок кликает слова → строка-предложение (3–5 слов) → подтверждение → проверка
    по таблице предложений текущего набора
  - счётчики: успехи (цель 3), «чушь» (лимит 5), «плохие» успехи (3 → особое стирание)
  - исходы: победа → `succeed()`; лимит чуши → стирание; 3 плохих → стирание с особой репликой
- `Game/scripts/resources/version2_config.gd` + `resources/configs/version2.tres` —
  длина предложения (3–5), лимиты, особые реплики (см. спецификацию)

**Критерий приёмки:** все три исхода воспроизводятся; реплики соответствуют таблице;
после стирания — экран стирания (шаг 8).

## Шаг 8. Экран стирания ⬜

**Цель:** наказание за провал версии 0.2: стирание и рестарт версии (без ограничений и счётчика — это MVP).

**Создаём:**
- `Game/scenes/effects/wipe_screen.tscn` + `scripts/effects/wipe_screen.gd` —
  затухание/«сброс» экрана, реплика `dad`, рестарт текущей версии (`Game.change_state` в ту же)
- Сброс состояния мини-игры и счётчиков при рестарте

**Критерий приёмки:** после стирания игрок возвращается в начало версии 0.2;
доверие НЕ сбрасывается (решение по умолчанию — поправь, если иначе).
