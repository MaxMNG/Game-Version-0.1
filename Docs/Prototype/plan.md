# План реализации прототипа Version 0.1

> Источник ТЗ: `References/GDD/Прототип/Прототип - Version 0.1.md`.
> Этот план — рабочий чеклист. Выполняем строго по шагам, каждый шаг завершаем
> проверкой по критериям приёмки. Статусы: ⬜ не начат / 🔄 в работе / ✅ готов.

**Общие правила для всех шагов:** ноль хардкода (все числа — в конфиги `.tres`),
наследование от `BaseMinigame` для мини-игр, общение через `Events`,
после каждого шага — импорт + дымовой тест (команды в `AGENTS.md`).

## Шаг 0. Контент-инфраструктура ✅

**Цель:** таблицы слов/предложений можно редактировать в CSV и конвертировать в игру.

**Создаём:**
- `Content/words_v01.csv` — 10 слов (спецификация: [content-words-v01.md](content-words-v01.md))
- `Content/sentences_v02.csv` — наборы слов + предложения (спецификация: [content-sentences-v02.md](content-sentences-v02.md))
- `Game/scripts/resources/word_entry.gd` — `class_name WordEntry` (word, type, trust_effect, speaker, reaction_text)
- `Game/scripts/resources/sentence_entry.gd` — `class_name SentenceEntry` (+ `set_id`, words)
- `Game/scripts/resources/content_table.gd` — обёртки-ресурсы с массивами записей
- `Tools/convert_content.py` — конвертер CSV → `Game/resources/content/*.tres`
- `Tools/check_sentences.py` — чекер покрытия наборов: перебор перестановок,
  непокрытые — в `Tools/uncovered_sentences.txt`
- Загрузка контент-таблиц в автолоад `Configs`

**Наполнение таблиц:** делаю я (черновик) → ты правишь в Excel. 10 слов: ≥1 хорошее, ≥1 плохое,
остальные нейтральные. Наборы v0.2: 3 штуки по 4–6 слов, в каждом 2–8 предложений
(мин. 1 плохое + 1 хорошее), полное покрытие осмысленных комбинаций —
проверяется чекером `Tools/check_sentences.py`.

**Критерий приёмки:** конвертер собирает `.tres` без ошибок; `Configs` отдаёт таблицы;
в игре доступны все 10 слов и наборы.

## Шаг 1. Фон всей игры ✅ (готов: комбо «Матрица + Дым»)

**Цель (достигнута):** живой фон всей игры — комбо «Матрица + Дым»;
реагирует на курсор и затухает обратно. Ничего не ждём, фон готов.

> Первый вариант («небула», fbm-чернила) не понравился — запаркован как запасной:
> `Game/scenes/effects/background_effect.tscn` + `scripts/effects/background_effect.gd` +
> `assets/shaders/background_effect.gdshader` + `NebulaConfig` / `nebula.tres`.
> Отмонтирован из `Main.tscn`, из игры ничего не тянет. Новый эффект — **на новой сцене**
> (старую не перезаписываем, чтобы можно было сравнить).

**Создаём:**
- Этап 0 ✅ Лаборатория: `Game/scenes/dev/background_lab.tscn` +
  `scripts/dev/background_lab.gd` — слот во весь экран, 4 кнопки
  (Кольцо/Матрица/Дымка/Комбо), панель живых настроек, Save в `.tres`.
  Несмонтированные эффекты честно говорят «ещё не готов».
- Этап 1 ✅ Кольцо-эквалайзер (референс `Небула1.jpg`):
  `assets/shaders/ring_background.gdshader` (бары — функция времени, магнит курсора),
  `scenes/effects/ring_background.tscn` + `scripts/effects/ring_background.gd`
  (контракт: `apply_config()`, `set_muted()`, `set_reveal()`/`play_appearance()`),
  `scripts/resources/ring_config.gd` + `resources/configs/ring.tres`
  (геометрия, дрожание, магнит, 3 цвета + мягкость градиента,
  внутренняя граница, прозрачность + общая альфа, длина 0–100,
  яркость, появление). Базовой окружности нет (убрана),
  магнит работает только рядом с полосой баров.
  Ручки в лаборатории: бары, радиус, дрожание, магнетизм, свечение, цвета.
- Этап 2 ✅ Матрица (3-я итерация): статичная сетка настоящих глифов из
  запечённого атласа (`Tools/bake_matrix_atlas.py` → `assets/atlases/matrix_glyphs.png`,
  94 символа: A–Z, a–z, 0–9, пунктуация). Падающих потоков нет; яркость ячейки =
  маска глифа × радиальный градиент от курсора × заряд движения (в покое держится
  минимальный пол `charge_floor` 0.1 + статичное свечение центра). Панель — 16 ручек.
- Этап 3 ✅ Дымка-lite: `smoke_background.gdshader` (2 слоя fbm + warp,
  гравитация к центру + виньетка, курсорный пуш с завихрением) +
  `smoke_background.tscn/.gd` + `smoke_config.gd` / `smoke.tres`
  (нейтральная серо-голубая палитра, `accent_intensity` дефолт еле заметный).
  Ручки в лаборатории (16 ручек).
- Этап 4 ✅ Комбо: `matrix_smoke_background.tscn` + `matrix_smoke_background.gd`
  (стек MatrixLayer снизу + SmokeLayer сверху; прозрачность дыма — uniform
  `amount` в шейдере, комбо дублирует материал и ставит туда `smoke_amount`,
  слои читают свои `matrix.tres` / `smoke.tres`) + `matrix_smoke_config.gd` /
  `matrix_smoke.tres` (доля дыма дефолт 0.35). Кнопка «4. Комбо» в лаборатории.
- Запасной вариант: `background_effect.*` + `nebula.tres` (не трогаем).
- Финал ✅ Победитель — комбо «Матрица + Дым»: смонтировано в `Main.tscn`
  как `Background` под `StateContainer`. Правки фона дальше — только через
  лабораторию (Save пишет в те же `.tres`, что грузит игра).

> Замечание: Save в лаборатории пишет через `ResourceSaver` — свойства,
> равные дефолтам скрипта, в `.tres` не попадут (поведение движка).
> Семантически файл корректен; для читаемости держим полный текст в репозитории.

**Контракт фона (общий для любого варианта, нужен шагам 2 и 4):**
- Полноэкранный `ColorRect`, `mouse_filter = IGNORE` (клики — сквозь фон).
- `set_muted(bool)` — приглушённый режим для меню/диалогов.
- Появление из темноты после вспышки интро (аналог `set_reveal()` / `play_appearance()`).
- Монтируется в `Main.tscn` под `StateContainer`.

**Критерий приёмки (выполнен):** фон красивый, но не отвлекает (это фон всей игры);
возмущение от курсора плавно затухает; 60 FPS на Compatibility.

## Шаг 5. Версия 0.1 — сбор слов ✅

**Реализовано:** `word_assembly.tscn/.gd` (наследник `BaseMinigame`), `floaty_symbol.tscn/.gd`,

**Отклонения от плана (решения пользователя):** строгий порядок букв (D→O→G) вместо

слова в таблице 3–5 букв) + CLEAR. Остальное по плану: 3 успеха → апгрейд, чушь — новый
набор без наказания, реакции и Trust из CSV.

**Цель:** мини-игра по ТЗ и [../Mechanics/word-assembly.md](../Mechanics/word-assembly.md).

**Создаём:**
- `Game/scenes/minigames/word_assembly.tscn` + `scripts/minigames/word_assembly.gd`
  (наследник `BaseMinigame`):
  - спавн облака: буквы текущего слова из `WordsTable` + 7–12 «мусорных» глифов;
    медленное плавание (синусоидальный дрейф), облако-сетка в центре
  - клик по символу — выделение зелёным свечением; повторный клик снимает;
    при 3 выбранных — проверка
  - проверка: буквы == слову из таблицы → успех (реплика `speaker` + `Trust.change(trust_effect)`);
    иначе — красное мигание + реплика `dad` + новый набор (без наказания)
  - 3 успеха → `succeed()` → запрос апгрейда
- `Game/scenes/ui/floaty_symbol.tscn` + `scripts/ui/floaty_symbol.gd` — кликабельный символ
- `Game/scenes/ui/trust_indicator.tscn` + `scripts/ui/trust_indicator.gd` —
  смайлик + стрелка ↑/↓, слушает `Events.trust_changed` (точных чисел не показывает)
- `Game/scripts/resources/version1_config.gd` + `resources/configs/version1.tres` —
  кол-во мусора, скорость плавания, слов для победы (3), реплика на «нет слова»

**Открытый вопрос (решу по умолчанию «да», поправь если не так):** порядок букв при выборе
не важен — засчитываем любую перестановку букв слова.

**Критерий приёмки:** 3 слова → апгрейд; «плохое» слово → −1 доверие и стрелка ↓;
«чушь» → красное мигание и повторный набор; проиграть невозможно.

## Шаг 11. Тест MCP godot-ai ⬜

**Контекст:** текущий godot-mcp покрывает логику, но неудобен (падения в отладчик,
капризный `game_mouse_move`, нет регрессии). Кандидат на замену/дополнение — godot-ai
(см. D3: пересмотр на этапе MVP).

**Делаем:** скачать godot-ai, подключить рядом с godot-mcp, прогнать на нём
типовые задачи (запуск, eval, клик-тест 0.1, скриншоты), сравнить и зафиксировать
решение в `DECISIONS.md`.

**Критерий приёмки:** вывод «оставляем godot-mcp / переходим на godot-ai / оба»
записан в журнал решений.
