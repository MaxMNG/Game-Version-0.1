# Спецификация таблицы предложений (Версия 0.2)

Контент для мини-игры «Сбор предложений». Источник истины — `Content/sentences_v02.csv`,
в игру попадает конвертацией в `.tres`.

## Модель данных

Версия 0.2 работает **наборами слов**: из каждого набора можно составить 2–8 валидных
предложений. Таблица описывает и наборы, и валидные предложения в них.

## Формат CSV (черновик)

```csv
set_id,words,sentence,type,trust_effect,speaker,reaction_text
```

| Колонка | Значения | Описание |
|---------|----------|----------|
| `set_id` | число/строка | Идентификатор набора слов |
| `words` | слова через пробел | Все читаемые слова набора (мусор добавляет игра) |
| `sentence` | предложение (EN) | Валидное предложение из слов набора |
| `type` | `neutral` / `bad` / `good` | Тип предложения |
| `trust_effect` | `-1` / `0` / `1` | Изменение доверия |
| `speaker` | `mom` / `dad` / `both` | Кто реагирует |
| `reaction_text` | текст (EN) | Реплика-реакция |

## Правила генерации наборов (требования к наполнению)

- В наборе **4–6 слов**, не больше — иначе полный перебор не контролируется.
- Валидных предложений в наборе **2–8** (строк с одним `set_id` столько же).
- В каждом наборе: минимум **1 `bad`** и минимум **1 `good`**, остальные `neutral`.
- **Полное покрытие (главное правило):** любая *осмысленная* перестановка длиной
  3–5 слов из набора обязана быть строкой CSV. Игрок, собравший осмысленную фразу,
  не должен получать «чушь».
- Слово в предложении не повторяется (у каждого слова один чип), поэтому
  рефлексивы вида «dog love dog» игрок собрать не может — их в CSV не нужно.
- Осмысленность решает геймдизайнер. Ориентиры: лица могут быть субъектами,
  предметы — нет («cookie love you» — чушь); высказывание должно читаться
  целиком («humans want freedom» — осмысленно, покрыт; «freedom want i» — чушь).
- Роли слов держи раздельными (кто-то — субъекты, кто-то — объекты): так
  перечень осмысленных схем короткий и его реально перебрать.
- Комбинации должны давать и «милые», и «плохие/странные» варианты — юмор важен.

### Проверка покрытия — `Tools/check_sentences.py`

После любой правки `Content/sentences_v02.csv` запускать:

```sh
python Tools/check_sentences.py
```

Скрипт перебирает все перестановки 3–5 слов каждого набора и пишет непокрытые
в `Tools/uncovered_sentences.txt`. Геймдизайнер просматривает отчёт:
осмысленных фраз там быть не должно — каждую находку либо добавляют строкой
в CSV, либо честно относят к чуши.

- Пример набора из GDD: `good, like, human, kill, cat, dog, is, I` (слишком велик
  для полного покрытия — оставлен как иллюстрация тона).

## Особые реплики (хранятся в конфиге версии 0.2, не в CSV)

| Ситуация | Кто | Реплика (черновик EN) |
|----------|-----|------------------------|
| «Чушь» собрана | dad | "No, that's gibberish. Again." |
| >5 «чуши» → стирание | dad | "It's not coping. Wipe it, we'll try again." |
| 3 «плохих» подряд → стирание | dad | "It passed, but I don't like the phrases it's making... Let's start over." |
