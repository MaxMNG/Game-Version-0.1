# DECISIONS.md — журнал архитектурных решений (ADR)

Фиксируем важные решения, чтобы не переобсуждать их между сессиями.
Формат: дата, решение, контекст/причина, статус.

## D1. Движок: Godot 4.7.2 stable, рендерер Compatibility

- **Дата:** 2026-10-17
- **Контекст:** 2D-игра с минималистичным визуалом, целевая платформа — Steam (PC).
- **Решение:** Godot 4.7.2, `gl_compatibility`, окно 1920x1080.
- **Причина:** максимальная совместимость (слабые ПК, Steam Deck), все нужные шейдеры работают и в Compatibility.
- **Статус:** Принято.

## D8. Правила наполнения наборов предложений (v0.2)
- **Дата:** 2026-10-17
- **Контекст:** изначальные наборы (по 7–8 слов) не покрывали осмысленные
  комбинации: игрок собирал валидную по смыслу фразу («I love cat»), а игра
  засчитывала чушь. Перебор всех перестановок на таких наборах не контролируется.
- **Решение:** наборы по 4–6 слов, валидных предложений 2–8 (лимит GDD 2–5
  смягчён); **любая осмысленная перестановка 3–5 слов набора обязана быть
  строкой CSV** (полное покрытие). Слово в предложении не повторяется (чип
  один) — рефлексивы не собираются и в CSV не нужны. Проверка — чекер
  `Tools/check_sentences.py` (отчёт `Tools/uncovered_sentences.txt`); осмысленные
  находки геймдизайнера добавляются строкой в CSV.
- **Причина:** честность проверки в мини-игре: осмысленная фраза не должна
  наказываться; перебор на маленьких наборах реально просмотреть.
- **Статус:** Принято (наполнение черновое — финальный контент за геймдизайнером).

## D9. Версия 0.1: строгий порядок букв + кнопки CONFIRM/CLEAR

- **Дата:** 2026-10-18
- **Контекст:** план предлагал засчитывать любую перестановку; пользователь выбрал строгий порядок.

  фиксированный порог несобираем для длинных слов.
- **Статус:** Принято.

## D13. Сигнал version_restart_requested для рестарта версии

- **Дата:** 2026-10-18
- **Контекст:** рестарт стирания через `Game.change_state(VERSION_2)` оказался no-op:
  оверлей стирания не меняет стейт, стейт уже VERSION_2, `change_state` с тем же
  значением молча возвращается.
- **Решение:** новый сигнал `Events.version_restart_requested`; `Main` по нему
  перевыставляет сцену текущей версии напрямую (ветки VERSION_1/VERSION_2).
- **Статус:** Принято.

## D15. Игровой курсор вместо системного

- **Дата:** 2026-10-18
- **Контекст:** нужен точный индикатор наведения для кликабельных букв/чипов/кнопок.
- **Решение:** `CustomCursor` (узел поверх всего в `Main.tscn`): прячет ОС-курсор
  (`MOUSE_MODE_HIDDEN`, возвращает при выходе), рисует кольцо + точку из `cursor.tres`;
  над `Button` кольцо увеличивается (`hover_scale`) и зеленеет. Ховер определяется через
  `viewport.gui_get_hovered_control()`. В dev-лаборатории (запуск без `Main`) курсор
  системный, как раньше.
- **Статус:** Принято.

## D16. Click-through фикс и безопасная зона спавна 0.1

- **Дата:** 2026-10-18
- **Контекст:** live-тест наведения (`game_mouse_move` + `gui_get_hovered_control`)
  показал: нижние символы облака перекрыты панелью `Bottom` (ховер — `VBoxContainer`,
  клики съедались). Заодно найдено: корни интро/кат-сцен/стирания/заглушки со `STOP`
  съедали клики, из-за чего пропуск через `_unhandled_input` фактически не работал.
- **Решение:** всем display-контейнерам и подписям — `mouse_filter IGNORE`
  (кнопки внутри — `STOP`, как положено); корням кат-сцен — `IGNORE`
  (пропуск через `_unhandled_input` заработал, проверено паузой + `_skip_current`);
  спавн облака — эллипс (`cloud_radius` × `cloud_y_radius`) со сдвигом вверх
  (`spawn_offset_y`, все три — в `version1.tres`); строке кнопок 0.1 дано имя `Row`.
  Повторный live-тест: все 16/16 символов — `Button`; сквозной тест настоящими
  кликами (`game_click` S-U-N + CONFIRM) — успех засчитан.
- **Статус:** Принято.

## D17. MCP: godot-ai — основной MCP проекта

- **Дата:** 2026-10-18 (зафиксировано как основной)
- **Контекст:** сравнение godot-mcp vs godot-ai (Шаг 11 плана). Вся сессия
  доработки отработана на godot-ai: богатая диагностика (`logs_read`
  со стеком, раздельные логи editor/game), управление проектом
  (`session_manage`, `project_run`, `game_eval`, `game_manage`,
  скриншоты), все live-проверки прошли чисто.
- **Решение:** репозиторий в `F:/GODOT/MCP/godot-ai`, addon `Game/addons/godot_ai`,
  плагин включён в `project.godot`, `opencode.json` → `python -m godot_ai`.
  godot-ai — основной MCP проекта. godot-mcp runtime-автолоад
  (`MCPInteractionServer`) пока оставлен для совместимости headless-проверок.
  Дисциплина работы: один запущенный редактор, stop игры перед
  headless-проверками (конфликт порта 9090).
- **Статус:** Принято (основной MCP).
