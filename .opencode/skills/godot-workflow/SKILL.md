# Регламент работы с Godot-проектом

## Пути

- Проект Godot: `Game/` (файл `Game/project.godot`)
- Движок: `F:/GODOT/Godot_v4.7.2-stable_win64_console.exe` (консольная сборка — видно вывод)
- MCP-сервер: `godot` (godot-mcp v3.1.0, настроен в `opencode.json`)

## Правила

1. Никаких числовых литералов в коде — все балансные числа живут в `Game/resources/configs/*.tres` (требование GDD).
2. Перед коммитом изменений в `Game/` всегда прогонять валидацию (см. ниже).
3. Стиль кода — только по `CodeStyle.md`.
4. Общение между системами — через сигналы автолоада `Events`, не напрямую.

## Валидация после изменений кода

```powershell
# Импорт ресурсов (после добавления новых файлов)
F:/GODOT/Godot_v4.7.2-stable_win64_console.exe --headless --path Game --import

# Дымовой тест: запуск на несколько кадров, ошибки парсинга будут в выводе
F:/GODOT/Godot_v4.7.2-stable_win64_console.exe --headless --path Game --quit-after 5
```

## Отладка запущенной игры через godot-mcp

1. Запустить игру: инструмент MCP `run_project` (автолоад `MCPInteractionServer` поднимет TCP на 127.0.0.1:9090).
2. Дальше — runtime-инструменты: `game_eval` (произвольный GDScript), `game_get_node_info`, `game_set_property`, `game_screenshot` и т.д.
3. После отладки остановить игру (`kill` процесса или `game_eval` с `get_tree().quit()`).

## Чеклист перед сдачей задачи

- [ ] `--import` и дымовой тест проходят без ошибок парсинга
- [ ] Новые числа вынесены в конфиги, а не захардкожены
- [ ] Обновлены затронутые документы в `Docs/` и `CHANGELOG.md`
- [ ] AGENTS.md актуален (если менялась структура/команды)
- [ ] UI-задача: визуальная ревизия пройдена (см. ниже), иначе задача несдана

## Визуальная ревизия (обязательна для UI-задач)

UI-задача без скриншот-пары и списка расхождений считается несданной.

1. `project_run` (godot-ai), дойти до нужного экрана (симуляция ввода через `game_manage`
   или дев-хук, см. «MCP-контур» ниже).
2. `editor_screenshot` на 1920×1080 и 1280×720 (720p раннер может пинить —
   см. «MCP-контур»).
3. Сверка по пикселям: с `Docs/Design/Style_guide/` (пока K1 не закрыт —
   дополнительно со скилом `ui-review` и/или референсом из ГДД), выписать расхождения.
4. Правки → повтор с шага 1. Итераций максимум 2, дальше — эскалация к человеку
   с парой «референс vs факт».
5. Финальная скриншот-пара — в отчёт.

Роли: рецензент (смотрит картинки) — только модель со зрением (кандидаты:
`gpt-6-luna`, `gemini-4-argon`; проверить на первой задаче) или человек.
Исполнитель (правит, гоняет запуск/скриншоты, готовит сравнение) — любая модель,
включая Muse Spark / GLM-flash / DeepSeek-flash. Если у текущей модели зрения нет —
скриншоты смотрит человек и возвращает список правок, шаг из процесса не убирается.

## MCP-контур (проверен в Этапе 1.6 F6 — рабочий шаблон ревизии)

1. Связь: `session_manage` (op list) — редактор должен быть ready; игра — stopped
   перед запуском (конфликт порта 9090, D17). Перед `project_run` всегда
   `project_manage` stop и проверка, что рестарт пошёл с новым run_token.
2. Детерминизм: дев-хук `user://f6_hook.json` (читается в `Main._ready`, файла
   нет — обычный запуск): `{"state": ..., "seed": N, "trust": N,
   "window": [W, H], "overlay": "wipe"|"upgrade"|"", "upgrade_is_final": bool}`.
   В прод-сборку файл не поставляется. После ревизии хук-файл удалить.
3. Съёмка: `project_run` (mode main/custom) → дождаться кадров → `editor_screenshot`
   (source game, max_resolution 0). Динамику ловить серией кадров; точный момент —
   через `game_manage` suspend (заморозка) перед финальным кадром.
4. Ограничения раннера godot-ai (зафиксированы): окно пинится на 1920×1080
   (хук window и смена вьюпорта не пробивают — 720p снимать вручную в редакторе);
   `node_set_property`/`custom_manage` на рантайм не действуют (только редактор).
5. Ловушки из F6 (проверять первым делом при «тема не применяется» или
   «ноды не видно»): вариациям темы нужен `base_type` (`*/base_type` в `.tres`,
   иначе `get_type_dependencies` вариацию не включает); якоря с отрицательной
   высотой прячут ноды за экран; `queue_redraw` в NOTIFICATION_DRAW = редрав
   каждый кадр; видимый первый кадр `AnimatedSprite2D` до play.
