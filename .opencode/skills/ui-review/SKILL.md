# UI Review — ревью визуального качества

Диагностика вида: профессионально ли, консистентно ли, отполировано ли — **не** проверка
удобства (юзабилити) и не логика. Источник — `design-review` (чеклист) + `refactoring-ui`
Workflow D (severity и схема находок), переложены на Godot и godot-ai.

Ключевой вопрос: посмотрит ли человек с насмотренным вкусом и подумает «сделано хорошо»
или «это делал разработчик»?

## По умолчанию — diagnose-only

Это ревью: находки и правки **не применяются** без явной просьбы. Только отчёт.
Правки — отдельным шагом после согласования.

## Фиксированный порядок обхода (не переставлять)

```
hierarchy → layout & spacing → typography → color → depth → images → finishing
```

Порядок причинный: проблемы иерархии меняют то, что считается проблемой отступов;
отступы — что считается проблемой рамок; финишные штрихи бессмысленны на сломанной
структуре.

Режимы обхода:
- **Focused** — названо направление («посмотри на цвета»): 1–2 раздела, один проход.
- **Sweep** (по умолчанию для «проверь») — весь чеклист по порядку.
- **Parallel** — большая поверхность, много экранов, **и пользователь согласен**: по
  субагенту на раздел, затем слияние по `(сцена, элемент, правило)`; при конфликте двух
  разделов побеждает более ранний в порядке обхода.

## Чеклист

### 1. Иерархия
| Хорошо | Плохо |
|--------|-------|
| Одно понятное primary-действие, визуально доминирует | Три равно стилизованные кнопки конкурируют |
| Squint-тест: самый важный элемент выделяется | Всё одного веса — взгляду не за что зацепиться |
| Прогрессивное раскрытие: важное видно, детали — по действию | Всё сразу — перегруз |
| Связанное сгруппировано (близость, рамки, фон) | Связанное разбросано, несвязанное впритык |
| Осмысленная пустота, обрамляющая контент | Пустота выглядит случайной (неровной, зажатой) |

### 2. Раскладка и отступы
| Хорошо | Плохо |
|--------|-------|
| Одинаковый отступ между всеми элементами группы/секции | У части 16, у части 24; padding шапки ≠ тела |
| Левые края контента выровнены по секциям | Заголовок с одним отступом, текст с другим, карточки с третьим |
| Простор, элементы не зажаты | Текст у краёв контейнера, кнопки впритык к полям |
| Контент следует явной сетке/контейнерной раскладке | Элементы расставлены свободно |
| Одинаковый вертикальный ритм (шкала отступов K1) | Случайные значения: 13, 27, 8 |

### 3. Типографика
| Хорошо | Плохо |
|--------|-------|
| Явная разница заголовок → подзаголовок → текст | Заголовки и текст одного размера/веса |
| Мера текста (шкала K1), легко читать | Строка во всю ширину, тяжело читать |
| Межстрочный растёт с длиной строки, падает с кеглем | Зажатый или избыточный интервал |
| Последовательная шкала кеглей | Случайные размеры без связи |
| Regular — текст, medium — подписи, semibold — заголовки | Всё жирное либо всё regular |
| Длинный текст сокращается с многоточием | Текст переполняет контейнер, ломается перенос, обрезан без многоточия |

### 4. Цвет и контраст
| Хорошо | Плохо |
|--------|-------|
| Семантические токены (`Accent`, `TextMuted`), не сырые хексы по месту | Литеральные цвета в сцене |
| Контраст ≥ 4.5:1 для обычного текста, ≥ 3:1 для крупного | Светло-серое на тёмном, тёмное на тёмном |
| Один цвет = одно значение везде (accent = действие) | Синий значит «кликабельно» там и «информация» тут |
| 2–3 цвета + нейтрали | Радуга без иерархии |
| Никакого серого текста на цветном фоне | Grey-on-color |

### 5. Глубина
| Хорошо | Плохо |
|--------|-------|
| Свет сверху: выпуклое — светлее верх, резкая тень снизу | Тени «в случайную сторону» |
| Одна-две ступени тени, применяются консистентно | У каждого компонента своя глубина тени |
| Единая шкала радиусов | Случайные радиусы: 3, 7, 10, 16 |

### 6. Компонентная консистентность
| Хорошо | Плохо |
|--------|-------|
| Один primary-стиль, один secondary, один destructive | 5 разных стилей кнопок |
| У всех панелей один радиус/тень/padding | Часть скруглена, часть острая, часть с тенью |
| Все поля одной высоты, рамки, focus-ring | Разные высоты/рамки/фокус |
| Единый радиус по шкале | Случайные радиусы |

### 7. Интерактив и состояния
| Хорошо | Плохо |
|--------|-------|
| Кнопки/ссылки/кликабельные панели реагируют на hover | Нет отклика — непонятно, что кликабельно |
| Видимый focus на всех интерактивных элементах | Focus-ring отсутствует или невидим на фоне |
| Активный пункт/tab отличается от неактивного | Активный выглядит как неактивный |
| Плавные переходы ~150–200 мс | Нет переходов (рывок) или медленно (тормозит) |
| Disabled визуально приглушён | Disabled выглядит кликабельным |

### Раскладка (обязательно)
- **1920×1080** и **1280×720** — без переполнений, обрезки, наездов.
- Тач-цели/кликабельные зоны достаточно крупные (≥ 44×44 px по площади).

## Severity

| Уровень | Значение | Пример |
|---------|----------|--------|
| **P0** | Иерархия рухнула, текст нечитаем, контраст провален WCAG — затронута удобность | Невидимый текст на фоне, кнопки разной высоты в строке |
| **P1** | Off-system значения, неясный групповой отступ, серое-на-цветном, неранжированные действия — затронута консистентность | Разнобой отступов, смешанные размеры шрифтов |
| **P2** | Нет полировки, неиспользованная глубина, дефолтный вид компонентов | Незначительные расхождения радиусов |

P0 сообщаем всегда, даже если спросили о другом.

## Верификация по пикселям

Чтение кода — не ревью дизайна. Рендери по пикселям:

1. `project_run` (godot-ai).
2. Дойти до нужного экрана (симуляция ввода через `game_manage`).
3. `editor_screenshot` на **1920×1080** и **1280×720**.
4. Судить по картинке: реальная мера, реальный контраст, групповые отступы, поведение раскладки.

Находки, полученные только чтением кода, помечаются как **unverified**. Скриншоты
прикладываем к находкам, где проблема визуальна (почти ко всем).

## Формат отчёта

```markdown
# UI Review: <экран>
**Дата**: YYYY-MM-DD
**Сцена**: <path к .tscn>
**Раскладки**: 1920×1080, 1280×720

## Общее впечатление
[1–2 предложения — профессионально / неотполировано / несолидно / чисто]

## Находки

| # | Lens | Severity | Location | Rule | Now | Proposed | Effort |
|---|------|----------|----------|------|-----|----------|--------|
| 1 | hierarchy | P0 | ... | §2.8 | ... | ... | S/M/L |
| 2 | spacing | P1 | ... | §3.6 | ... | ... | ... |

## Что сделано хорошо
[паттерны, которые удались и их нужно сохранить]

## Топ-3 правки
1. [самое заметное по визуальному эффекту]
2. [второе]
3. [третье]
```

## Подсказки

- Squint-тест — быстрее всего находит проблемы иерархии.
- Несогласованность компонентов — самая частая проблема UI, сделанного разработчиком.
- «Выглядит не так» обычно про отступы — сначала проверяй их.
- Не можешь назвать проблему — сравни с хорошо сделанным экраном того же жанра.
- Сверяй с `Docs/Design/visual-language.md`: соответствие дизайн-языку — часть ревью.
- Проверяй поведение при пустых и при очень длинных данных.

## Когда НЕ применять

- Задачи без визуальной поверхности: логика, автолоады, конвертеры.
- Правки, уже описанные как рефакторинг без изменения вида.
- Когда нужен именно конструктор нового экрана — сначала `godot-ui`, потом ревью результата.
- Не заменяет юзабилити-проверку поведения (клики, потоки) — это отдельное ревью.
